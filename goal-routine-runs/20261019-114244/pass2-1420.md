# Pass 2 — issue #1420 → PR #1436

Issue: gnoviawan/termul#1420 — Idle-stop auto-resume (and other non-reload reopens) drop all MCP servers, including Termul Canvas.

Claim: draft PR #1436 opened on `routine/1420-mcp-reopen-attach` before any code (claim-then-build, Unattended runs policy).

## Repro (on dev, code-level, issue-confirmed)

- `use-idle-stop-auto-resume.ts` → `openHistorySession(sessionId)` with no options.
- `acp-store/slices/session.ts` `openHistorySessionInner` forwarded `options?.mcpServers` (undefined) into all three `acpApi.loadSession/resumeSession` calls (L1155/L1219/L1260 pre-fix).
- Wire contract (`ws-transport.ts` L1131/L1155 + `acp-api.ts` L1067): omitted `mcpServers` → host `prepare_reopen_mcp` returns `(None, None)` → no client MCP list AND no host plan server (canvas, plan, set_session_title, ask_user). Exactly the issue's observed `mcp__termul__*` removal.
- Verified failing-before via stashed source: regression test fails without the fix.

## Fix

`src/renderer/stores/acp-store/slices/session.ts` — in `openHistorySessionInner`, after the capability wait resolves `liveAgentId`:

```ts
const capabilities = get().agents[liveAgentId]?.capabilities ?? null
const mcpServers =
  options?.mcpServers ?? selectMcpServersForAgent(get().mcpServers, capabilities).servers
```

The three `acpApi.loadSession/resumeSession` calls now pass the resolved `mcpServers`. Same defaulting `createSession` already uses (L1535 pre-fix); reload's explicit list still wins via `options?.mcpServers`. Covers idle-stop auto-resume, sidebar/history open, manual Resume chat, and the discovered-session-attach fallback paths that run through `openHistorySessionInner`.

Doc comments updated: `ReopenCallOptions` (acp-transport/types.ts), `OpenHistoryOptions` (acp-store/types.ts).

No Rust change: host semantics (`prepare_reopen_mcp`, WS handlers `load_session`/`resume_session` `mcp_servers: Option<Vec<...>>` with `#[serde(default)]`) already support a present list; only the renderer never sent one on these paths.

## Test

`history-session.test.ts` — "openHistorySession attaches the registry MCP servers when the caller omits mcpServers (idle-stop auto-resume, #1420)": idle-reaped closed chat, no live owner → fresh spawn → asserts `acp_load_session` receives `mcpServers` = the two enabled registry servers (wire-shaped, `headers: []` re-filled), disabled server excluded, session active.

Five strict-payload assertions in the same file updated to expect `mcpServers: []` (empty registry in `FRESH`) — an empty list still attaches the host plan server per the wire contract, which is the intended new behavior.
